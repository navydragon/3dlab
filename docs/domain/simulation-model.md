## 1. Назначение документа

Этот документ определяет математическую модель первого MVP:

**гидравлический экскаватор + автосамосвалы + разработка, погрузка и транспортирование грунта.**

Документ является source of truth для:

- входных параметров;
- единиц измерения;
- формул;
- вычисляемых показателей;
- допущений;
- правил интерпретации;
- тестовых сценариев;
- ожидаемых результатов автоматических тестов.

Codex не должен самостоятельно изменять формулы, вводить дополнительные коэффициенты или подменять расчёт заранее заданными результатами без изменения этого документа.

---

## 2. Цель модели MVP

Модель предназначена прежде всего для обучения причинно-следственным связям.

Она должна позволить студенту исследовать цепочку:

```text
параметры экскаватора
→ время загрузки автомобиля
→ цикл автосамосвала
→ обеспеченность экскаватора транспортом
→ производительность комплекса
→ простои и ожидание
→ продолжительность работ
→ эксплуатационные затраты
```

Модель не предназначена для:

- рабочего проектирования реального объекта;
- выбора техники без инженерной проверки;
- формирования нормативной производительности;
- сметного расчёта;
- календарного планирования реального строительства;
- оценки безопасности производства работ.

---

## 3. Тип модели

Первая версия использует **детерминированную циклическую модель**.

Она предполагает:

- один экскаватор;
- один фронт загрузки;
- одинаковые автосамосвалы;
- одинаковый маршрут;
- постоянные средние скорости;
- постоянное время разгрузки;
- отсутствие случайной вариативности;
- отсутствие отказов;
- отсутствие заторов на маршруте;
- отсутствие отдельного ограничения на пункте разгрузки;
- установившийся повторяющийся цикл.

Модель описывает средние условия и специально упрощена для первого учебного MVP.

---

## 4. Базис объёма

Все объёмы в первой версии задаются в **рыхлом объёме материала**:

```text
м³ рыхлого грунта
```

Обозначение в интерфейсе:

```text
м³ (рыхл.)
```

Это правило распространяется на:

- вместимость ковша;
- фактический объём материала в ковше;
- вместимость кузова автосамосвала;
- производительность;
- объём работ.

### Почему это важно

Нельзя смешивать в одном расчёте:

- объём в естественном залегании;
- рыхлый объём;
- уплотнённый объём

без специальных коэффициентов преобразования.

В MVP коэффициенты разрыхления и уплотнения сознательно не вводятся.

Их добавление потребует новой версии модели.

---

## 5. Единицы измерения

Внутренняя расчётная модель должна использовать явно определённые единицы.

| Величина | Единица |
|---|---|
| Вместимость ковша | м³ (рыхл.) |
| Вместимость кузова | м³ (рыхл.) |
| Объём работ | м³ (рыхл.) |
| Время рабочего цикла экскаватора | с |
| Время загрузки | мин |
| Время разгрузки | мин |
| Расстояние | км |
| Скорость | км/ч |
| Производительность | м³/ч |
| Продолжительность работ | ч |
| Коэффициенты | безразмерные |
| Стоимость машино-часа | у.е./маш·ч |
| Общие затраты | у.е. |
| Стоимость единицы объёма | у.е./м³ |

`у.е.` означает **условную денежную единицу**.

В первой версии экономические данные являются учебно-иллюстративными и не должны визуально выдаваться за реальные рыночные цены.

# 6. Входные параметры

## 6.1. Параметры экскаватора

### `bucket-capacity`

Геометрическая вместимость ковша.

Обозначение:

```text
q_bucket
```

Единица:

```text
м³ (рыхл.)
```

---

### `bucket-fill-factor`

Коэффициент фактического наполнения ковша.

Обозначение:

```text
k_fill
```

Безразмерный.

Для модели:

```text
k_fill > 0
```

Типичный диапазон интерфейса для учебного эксперимента должен быть определён отдельно после проверки предметным экспертом.

Codex не должен придумывать нормативный диапазон.

---

### `excavator-cycle-time`

Продолжительность одного полного рабочего цикла экскаватора.

Обозначение:

```text
t_cycle
```

Единица:

```text
с
```

В MVP цикл включает в агрегированном виде:

```text
копание
+ подъём
+ поворот к месту разгрузки
+ разгрузку ковша
+ обратный поворот
```

---

### `time-utilization-factor`

Коэффициент использования рабочего времени.

Обозначение:

```text
k_time
```

Диапазон:

```text
0 < k_time <= 1
```

Он используется как общий коэффициент перехода от идеальной производительности 60-минутного часа к учебной эксплуатационной производительности.

Пример:

```text
k_time = 0.83
```

примерно соответствует 49.8 эффективным минутам из 60.

Это не нормативное значение.

---

## 6.2. Параметры автосамосвала

### `truck-capacity`

Полезный объём кузова в той же объёмной базе, что и ковш.

Обозначение:

```text
V_truck
```

Единица:

```text
м³ (рыхл.)
```

---

### `haul-distance`

Расстояние от места загрузки до места разгрузки в одну сторону.

Обозначение:

```text
D
```

Единица:

```text
км
```

---

### `loaded-speed`

Средняя скорость движения с грузом.

Обозначение:

```text
v_loaded
```

Единица:

```text
км/ч
```

---

### `empty-speed`

Средняя скорость обратного движения без груза.

Обозначение:

```text
v_empty
```

Единица:

```text
км/ч
```

---

### `unloading-time`

Время разгрузки и включённых в него простых манёвров на пункте разгрузки.

Обозначение:

```text
t_unload
```

Единица:

```text
мин
```

В MVP отдельный параметр `spotting-time` не используется.

При необходимости он может быть добавлен в следующую версию модели.

---

### `truck-count`

Количество одинаковых автосамосвалов в системе.

Обозначение:

```text
N
```

Тип:

```text
positive integer
```

---

## 6.3. Параметры производственной задачи

### `work-volume`

Объём материала, который необходимо разработать, погрузить, перевезти и разгрузить.

Обозначение:

```text
V_work
```

Единица:

```text
м³ (рыхл.)
```

## 6.4. Экономические параметры

### `excavator-hourly-cost`


Единица:

```text
у.е./маш·ч
```

---

### `truck-hourly-cost`

Учебная стоимость одного машино-часа одного автосамосвала.

Обозначение:

```text
C_truck
```

Единица:

```text
у.е./маш·ч
```

# 7. Производительность экскаватора как отдельной машины

## 7.1. Фактический объём материала за один цикл

```text
q_eff = q_bucket × k_fill
```

где:

- `q_eff` — фактический объём материала в ковше;
- `q_bucket` — вместимость ковша;
- `k_fill` — коэффициент наполнения.

---

## 7.2. Число циклов за идеальный час

Если `t_cycle` задан в секундах:

```text
cycles_per_hour_60 = 3600 / t_cycle
```

---

## 7.3. Теоретическая производительность экскаватора

```text
Q_exc_60 = q_eff × 3600 / t_cycle
```

Единица:

```text
м³/ч
```

Это производительность для условного непрерывного 60-минутного часа без дополнительных потерь времени.

---

## 7.4. Учебная эксплуатационная производительность экскаватора

```text
Q_exc = Q_exc_60 × k_time
```

или:

```text
Q_exc = q_bucket × k_fill × 3600 / t_cycle × k_time
```

---

# 8. Загрузка автосамосвала экскаватором

## 8.1. Число ковшей на один автосамосвал

В MVP используется дискретное число рабочих циклов.

```text
bucket_passes = ceil(V_truck / q_eff)
```

где `ceil()` означает округление вверх до целого числа.

Это отражает учебную идею:

> Автосамосвал нельзя загрузить дробным количеством полных циклов экскаватора; последний ковш может быть использован не полностью.

---

## 8.2. Номинальное время загрузки одного автосамосвала

```text
t_load = bucket_passes × t_cycle / 60
```

Единица:

```text
мин
```

`k_time` на этом шаге не применяется.

Он применяется позднее к итоговой производительности системы как общий коэффициент использования рабочего времени.

---

## 8.3. Загрузочная производительность для данного типа автосамосвала

Из-за дискретного числа ковшей экскаватор может не использовать весь потенциальный объём последнего ковша.

Поэтому для конкретной пары:

```text
экскаватор + кузов автосамосвала
```

определяется отдельный потолок:

```text
Q_loading_ceiling_60 = V_truck × 60 / t_load
```

Единица:

```text
м³/ч
```

Это значение может быть немного меньше `Q_exc_60`.

---

# 9. Транспортный цикл автосамосвала

## 9.1. Движение с грузом

```text
t_loaded = D / v_loaded × 60
```

Единица:

```text
мин
```

---

## 9.2. Возврат порожнего автосамосвала

```text
t_empty = D / v_empty × 60
```

Единица:

```text
мин
```

---

## 9.3. Время вне загрузки

```text
t_away = t_loaded + t_unload + t_empty
```

---

## 9.4. Свободный цикл автосамосвала без очереди

```text
t_truck_free = t_load + t_away
```

или развёрнуто:

```text
t_truck_free =
    t_load
    + t_loaded
    + t_unload
    + t_empty
```

В эту величину не входит ожидание в очереди к экскаватору.

---

# 10. Баланс экскаватора и автосамосвалов

## 10.1. Match factor

Для одного экскаватора:

```text
MF = N × t_load / t_truck_free
```

Интерпретация:

```text
MF < 1
```

транспортное звено недостаточно для непрерывной загрузки; экскаватор часть времени ждёт.

```text
MF ≈ 1
```

комплект близок к балансу в рамках детерминированной модели.

```text
MF > 1
```

транспортное звено способно полностью загрузить экскаватор; появляется вероятность/необходимость ожидания автосамосвалов.

---

## 10.2. Минимальное целое число автосамосвалов для насыщения загрузочного звена

```text
N_balance = ceil(t_truck_free / t_load)
```

Это учебная оценка.

Она не является автоматической рекомендацией для реального проекта.

---

# 11. Загрузка экскаватора транспортом

Вводится показатель структурной загрузки экскаватора транспортным звеном:

```text
U_exc_transport = min(1, MF)
```

Диапазон:

```text
0 ... 1
```

Например:

```text
0.75
```

означает, что в идеализированной циклической системе транспорт обеспечивает загрузочную работу примерно на 75% потенциального загрузочного времени.

---

## 11.1. Доля простоя экскаватора из-за недостатка транспорта

```text
excavator_idle_share = 1 - U_exc_transport
```

Это **не общий простой машины на реальной стройплощадке**.

Показатель отражает только недостаток транспортного звена в данной упрощённой модели.

---

# 12. Производительность механизированного комплекса

## 12.1. Сырая производительность до коэффициента использования времени

```text
Q_system_60 =
    Q_loading_ceiling_60 × U_exc_transport
```

Эквивалентная форма:

```text
Q_system_60 =
    min(
        Q_loading_ceiling_60,
        N × V_truck × 60 / t_truck_free
    )
```

---

## 12.2. Учебная эксплуатационная производительность комплекса

```text
Q_system = Q_system_60 × k_time
```

Это основной показатель производительности MVP.

Единица:

```text
м³/ч
```

---

# 13. Ожидание автосамосвалов

В детерминированной модели очередь появляется после насыщения экскаватора транспортом.

## 13.1. Ожидание одного автосамосвала за цикл

```text
t_truck_wait =
    max(
        0,
        N × t_load - t_truck_free
    )
```

Интерпретация:

- если значение равно `0`, очередь в идеализированном установившемся цикле отсутствует;
- если значение больше `0`, автосамосвалы проводят часть цикла в ожидании загрузки.

---

## 13.2. Реализованный цикл автосамосвала

```text
t_truck_realized =
    t_truck_free + t_truck_wait
```

---

## 13.3. Доля ожидания автосамосвала

```text
truck_wait_share =
    t_truck_wait / t_truck_realized
```

если:

```text
t_truck_realized > 0
```

Иначе расчёт должен считаться невалидным.

---

# 14. Продолжительность выполнения заданного объёма

```text
project_duration =
    V_work / Q_system
```

Единица:

```text
ч
```

Расчёт допустим только при:

```text
Q_system > 0
```

---

# 15. Экономическая модель MVP

Экономический слой намеренно укрупнён.

Он должен показать причинную связь, а не заменить реальную смету.

---

## 15.1. Стоимость машино-часа комплекса

```text
C_system_hour =
    C_exc + N × C_truck
```

---

## 15.2. Общие эксплуатационные затраты

```text
C_total =
    project_duration × C_system_hour
```

---

## 15.3. Стоимость единицы объёма

```text
C_unit =
    C_total / V_work
```

Единица:

```text
у.е./м³
```

---

## 15.4. Важная учебная интерпретация

Увеличение количества автосамосвалов одновременно:

- увеличивает стоимость одного часа работы комплекса;
- может повысить производительность;
- может сократить продолжительность;
- после насыщения экскаватора почти перестаёт повышать производительность;
- при этом продолжает увеличивать стоимость часа.

Поэтому минимальное время выполнения работ не обязано совпадать с минимальной стоимостью.

---

# 16. Порядок расчёта

Расчёт должен выполняться в строго определённой последовательности.

```text
1. validate inputs

2. q_eff
3. Q_exc_60
4. Q_exc

5. bucket_passes
6. t_load
7. Q_loading_ceiling_60

8. t_loaded
9. t_empty
10. t_away
11. t_truck_free

12. MF
13. N_balance

14. U_exc_transport
15. excavator_idle_share

16. Q_system_60
17. Q_system

18. t_truck_wait
19. t_truck_realized
20. truck_wait_share

21. project_duration

22. C_system_hour
23. C_total
24. C_unit
```

# 18. Различие двух показателей производительности экскаватора

В UI важно не смешивать:

### Производительность экскаватора как отдельной машины

```text
Q_exc
```

и:

### Фактическую производительность механизированного комплекса

```text
Q_system
```

Пример учебного объяснения:

> Экскаватор технически способен разрабатывать больше материала, чем фактически перемещает весь комплекс, если транспорт не успевает обслуживать загрузочный фронт.

# 19. Базовый учебный сценарий

Числа ниже являются **иллюстративными тестовыми данными**, а не характеристиками конкретной реальной модели техники.

```yaml
scenarioId: base-earthworks-scenario

excavator:
  bucketCapacityM3Loose: 1.2
  bucketFillFactor: 0.90
  cycleTimeSeconds: 24
  timeUtilizationFactor: 0.83
  hourlyCostCU: 180

truck:
  capacityM3Loose: 12
  haulDistanceKm: 2
  loadedSpeedKmh: 24
  emptySpeedKmh: 32
  unloadingTimeMinutes: 1
  hourlyCostCU: 70

task:
  workVolumeM3Loose: 1000
```

`CU` = условная денежная единица.

# 23. Валидация входов

Расчёт не должен выполняться при невалидных данных.

Минимальные правила:

```text
bucketCapacity > 0
bucketFillFactor > 0
cycleTimeSeconds > 0
0 < timeUtilizationFactor <= 1

truckCapacity > 0
haulDistance >= 0
loadedSpeed > 0
emptySpeed > 0
unloadingTime >= 0
truckCount >= 1 and integer

workVolume > 0

excavatorHourlyCost >= 0
truckHourlyCost >= 0
```

---

# 24. Zero-distance scenario

Допускается:

```text
haulDistance = 0
```

В таком случае:

```text
t_loaded = 0
t_empty = 0
```

но остаются:

- загрузка;
- разгрузка.

Это допустимый технический edge case модели, хотя в учебном интерфейсе значение `0 км` может быть исключено из обычного slider range.

---

# 25. Ошибки вычисления

Модель должна возвращать структурированную ошибку, а не `NaN` или `Infinity`, если:

- входы невалидны;
- делитель равен нулю;
- `Q_system <= 0`;
- отсутствует обязательный параметр;
- единицы несовместимы.

UI не должен исправлять математические ошибки скрытыми fallback-значениями.

---

# 26. Округление

Внутри расчёта значения не округляются, кроме:

```text
bucket_passes = ceil(...)
N_balance = ceil(...)
```

Округление для отображения выполняется только в presentation layer.

Рекомендуемый UI:

- объёмы: 1–2 знака;
- время: 1–2 знака;
- производительность: 1 знак;
- проценты: 0–1 знак;
- денежные показатели: 0–2 знака.

Это UI-рекомендация, а не часть математического ядра.

---

# 27. Детерминизм

Для одинаковых входных параметров и одинаковой версии модели результат должен быть идентичен.

```text
same inputs
+
same model version
=
same outputs
```

В `earthworks-deterministic-v1` запрещено использовать случайные числа.

# 28. Разделение simulation core и UI

Расчётная функция не должна знать:

- какой экран открыт;
- существует ли 3D;
- какая машина выделена;
- какой slider используется;
- какой framework используется;
- какой язык интерфейса выбран.

Концептуальный контракт:

```text
SimulationInput
→ calculate()
→ SimulationResult
```

---

# 29. Разделение simulation core и 3D

3D-анимация может визуализировать:

- рабочий цикл;
- загрузку;
- движение;
- очередь;
- простой.

Но анимация не должна быть источником расчётного времени.

Например:

```text
визуальная анимация загрузки = 8 секунд экранного времени
```

не означает:

```text
расчётное t_load = 8 секунд
```

Анимация может масштабироваться для удобства обучения.

### `near-balanced`

```text
MF >= 1
```

Эти статусы не должны автоматически говорить студенту:

```text

```

# 32. Что модель не учитывает

`earthworks-deterministic-v1` сознательно не моделирует:

- вероятностное время циклов;
- различия между отдельными водителями;
- случайное ожидание;
- отказ техники;
- техническое обслуживание;
- пересменки;
- заправку;
- погодные условия;
- уклоны;
- сопротивление качению;
- качество временной дороги;
- разгон и торможение;
- ограничения скорости по отдельным участкам;
- встречное движение;
- однополосные участки;
- затор на разгрузке;
- несколько экскаваторов;
- разные типы автомобилей в одной системе;
- изменение характеристик грунта;
- плотность материала;
- ограничение по массе вместо объёма;
- разрыхление;
- уплотнение;
- возврат неполностью загруженного автомобиля;
- реальные тарифы;
- топливо;
- амортизацию;
- ремонт;
- стоимость оператора отдельно;
- налоги и накладные расходы.

Это не ошибки MVP.

Это границы первой модели.

# 33. Путь к следующей версии модели

После валидации MVP модель может развиваться поэтапно.

### `earthworks-deterministic-v2`

Возможные дополнения:

- spotting time;
- разные базы объёма;
- коэффициент разрыхления;
- плотность;
- ограничение кузова по объёму и грузоподъёмности;
- разные скорости по сегментам маршрута.

### `earthworks-discrete-event-v1`

Следующий качественный уровень:

- очереди;
- вариативность времени;
- распределения;
- несколько ресурсов.

Переход к discrete-event модели не должен менять предметные сущности `Machine`, `Process`, `ProductionSystem` и `Scenario`.

# 34. Методологическая опора

Формулы MVP используют общепринятые для учебных расчётов строительных машин идеи:

- производительность циклической машины через объём за цикл, продолжительность цикла и коэффициент использования времени;
- время транспортного цикла как сумму загрузки, движения с грузом, разгрузки и возврата;
- подбор количества транспортных единиц через отношение полного цикла транспорта к времени обслуживания загрузочной машиной;
- ограничение производительности комплекса наиболее медленным/ограничивающим звеном;
- рост ожидания транспорта после насыщения загрузочной машины.

Для дальнейшей предметной верификации рекомендуются:

1. **Volvo Construction Equipment — Excavator and Hauler Pairing Guide.**  
   Использует число ковшей, цикл экскаватора, цикл автосамосвала и сопоставление загрузочной и транспортной техники.

2. **FHWA — Construction of Portland Cement Concrete Pavements, Participant's Manual.**  
   Демонстрирует расчёт числа автомобилей из требуемого темпа и полного транспортного цикла, включающего загрузку, движение и разгрузку.

3. **U.S. Army FM 5-434, Earthmoving Operations.**  
   Классический учебный источник по производительности землеройно-транспортных комплексов и подбору числа транспортных единиц.

4. **New Mexico Energy, Minerals and Natural Resources Department — Truck Optimization calculations.**  
   Пример инженерного расчёта: число циклов загрузочной машины на автомобиль, loading time, truck cycle time и производительность комплекта.

Перед использованием системы для реальных инженерных решений формулы, коэффициенты и исходные данные должны быть проверены предметными экспертами и привязаны к применимым нормативным/справочным источникам.

# 36. Требования к explainability

Для каждого основного результата simulation core или слой интерпретации должен позволять показать пользователю:

- название показателя;
- значение;
- единицу;
- какие входы на него влияют;
- краткую формулу или логику;
- учебное объяснение.

Пример:

```text
Производительность комплекса: 82.1 м³/ч

Почему:
2 автосамосвала не успевают полностью обеспечить экскаватор транспортом.

Match factor: 0.66
Простой экскаватора из-за недостатка транспорта: 34.0%
```

Задача — исключить «чёрный ящик».

# 37. Acceptance criteria модели

Математическая модель MVP считается готовой к реализации, когда:

- все входы имеют явные единицы;
- объёмная база едина;
- формулы однозначны;
- различаются `Q_exc` и `Q_system`;
- число ковшей дискретно;
- изменение количества транспорта меняет баланс;
- недостаток транспорта создаёт простой экскаватора;
- избыток транспорта создаёт ожидание автомобилей;
- производительность перестаёт расти после насыщения экскаватора;
- увеличение расстояния при неизменном числе автомобилей снижает производительность;
- стоимость считается из количества машин и продолжительности;
- тестовые сценарии воспроизводятся автоматически;
- модель не зависит от UI и 3D;
- illustrative values явно отделены от реальных технических данных.

---

## 38. Главная формула учебной модели

```text
Machine parameters
→ Loading time
→ Truck cycle
→ Match factor
→ Fleet utilization
→ System productivity
→ Duration
→ Operating cost
→ Engineering-economic interpretation
```

MVP должен позволить студенту не только увидеть результат этой цепочки, но и понять причину каждого перехода.
